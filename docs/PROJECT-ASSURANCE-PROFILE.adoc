= Project Assurance Profile

Subject/version:: IDApTIK, as of commit `be1369f` (2026-07-20)
Assurance status:: draft
Observation model and boundary:: Correctness claims are limited to what compiles, passes CI (CodeQL, existing test suites), and has been manually exercised by the maintainer. No independent testing, fuzzing, or audit has been performed. The FFI boundary (`crates/idaptik-ffi`) and IDApTIK's network client/launcher integration (`crates/idaptik-net`, `scripts/multiplayer-runtime.sh`) are unverified beyond tests and manual use. The network-facing relay was extracted to `metadatastician/burble` and is outside this repository's assurance boundary.
Assumptions and evidence:: Assumes Rust's memory-safety guarantees hold except across the explicit unsafe C-ABI boundary in `idaptik-ffi`, which is not yet independently verified (estate triage flagged `UNVERIFIED_RUST` and `DIRECT_FFI_NO_UNIFIED_API_ADAPTER` for this repo; both still apply — the Zig adapter does not exist and no UnifiedApiAdapter authority has been located). One piece of boundary evidence now exists: an Idris2 model of the exported C ABI (`crates/idaptik-ffi/abi`) is typechecked under `%default total` and gated in CI (`just abi-model-check`), proving the header's ownership and shape contracts at the model level. No formal verification of the Rust implementation itself; no Creusot obligations discharged yet (issue #103 amendment).
Known limitations/residual risk:: No security audit; no fuzzing of the FFI surface; single maintainer means bus-factor risk on review capacity.
Responsible authority and review date:: `MAINTAINERS` (@metadatastician); 2027-01-20 (placeholder, first review since initial adoption)
